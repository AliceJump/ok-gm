# 本地 DMM 登录、更新和启动助手（实验功能）

助手使用明确配置的本地 HTTP 代理，获取学园偶像大师的新启动参数，并校验官方游戏下载清单。
ok-gm 侧栏中位于「游戏启动器」。默认启用本地助手和自动更新；代理设置与全局设置中的「DMM 启动助手」共享。

## 软件内使用

1. 在启动器粘贴一个日本节点分享链接并点击「保存节点」，或点击「导入 JSON 文件」。导入通过校验后自动启用「使用独立 Xray 节点」。也可关闭此项，使用 v2rayN 的本地 HTTP 入口，默认 `http://127.0.0.1:10808`。
2. 点击「浏览器登录」，使用常用浏览器的已保存密码；或点击「复用 DMM 登录态」只读导入现有凭证。
3. 保持「启动前自动检查并更新游戏」开启，点击「启动游戏」。日常任务通过框架启动游戏时也使用相同流程。

启动顺序为：启动独立 Xray（或已配置的 VPN）→ 读取所选账号 → 检查会话 → 获取清单 → 下载并校验更新 → 获取新启动参数 → 启动游戏。
更新失败会停止启动。下载进度在页面显示，页面操作可取消并在下次续传。游戏已经运行时不会更新其文件。
登录过期时先尝试 Cookie 授权，失败后打开常用浏览器；不会再次读取或导出浏览器密码。
更新实际发生时需退出游戏、DMM Player 和 Celestite，助手会检查占用并给出提示。

本实现复用 DMM 的已有安装目录，目前不支持全新安装游戏。游戏进程自身的网络路径由游戏和系统决定；
这里的显式代理覆盖启动器的认证、版本检查及文件下载，不承诺强制代理游戏的全部连接。

## 独立节点列表与故障切换

支持 VLESS、VMess、Trojan、无插件 Shadowsocks 分享链接，以及 Xray 单个出站 JSON。
每次导入追加一个节点，最多保存 32 个；完全相同的出站会更新名称并重新启用，避免重复。
页面可选择「下次优先使用」、停用或移除节点。旧版单节点文件会自动兼容为列表中的一个节点。
完整 Xray JSON 必须只含一个受支持的代理出站；其中的其他监听、路由、API、日志和直连出站不会导入。
依赖其他出站或本地证书文件的节点会报错。复杂传输可使用 JSON，最终以 Xray 内核配置校验结果为准。

节点配置以 Windows DPAPI 加密保存到 `%LOCALAPPDATA%\ok-gm\dmm-helper\node.dpapi`。
输入框隐藏链接，配置通过标准输入交给内核，不写明文运行配置或节点凭据日志。
独立内核位于同目录的 `xray-core\xray.exe`：优先复制打包的 `vendor\xray\xray.exe` 或本机已安装的 v2rayN 内核；
不存在时，使用本地代理下载官方 XTLS/Xray-core Windows 发布包并验证发布资产的 SHA-256。
复制完成后不再依赖 v2rayN 进程。打包发行时可附带内核，并保留上游许可证文件。

每次在线操作创建仅监听 `127.0.0.1` 的临时端口。单次请求仍只使用一个明确的出站；各次操作按列表顺序轮换开始节点。
握手、连接、TLS 或超时失败时自动换到本次尚未尝试的下一个启用节点；HTTP 403、502、503、504 也触发切换。
HTTP 401、DMM 登录失效及业务拒绝不会被当作坏节点处理。
切换会重启自己的内核，入口端口保持相同，最多尝试本次启用列表中的每个节点一次。
API 响应中途断开和下载流中断也支持切换；下载换节点后用 Range 继续，并照常校验完整文件后替换。
换节点失败或全部节点不可用时停止，不回退到 v2rayN 或直连。
浏览器自身的请求不经过助手的重试适配器，浏览器页面卡住时仍需刷新或重新发起登录。
操作结束会退出自己的内核，进程异常退出时 Windows Job Object 也会清理该内核。
登录浏览器会临时使用同一入口；游戏进程自身的连接不在此承诺范围内。
指定节点固定的是服务器配置，节点提供商改变该服务器出口位置时仍需自行确认日本出口。

## 多账号登录文件

1. 已经在助手登录的账号：填写编号（例如 `1`）与名称，点击「保存当前登录态」。这是离线快照，不额外验证服务器有效性。
2. 另一个账号：先关闭游戏，填写新的编号与名称，点击「新账号登录并保存」，在常用浏览器登录目标账号。或在 DMM Player 换好账号后点击「记录当前 DMM 为新账号」。新账号通过服务器身份检查后才归档。
3. 切换时先关闭游戏，在下拉列表选择账号，点击「切换所选账号」，再启动游戏。仅选中下拉项不会切换当前账号。

编号支持 1～40 位字母、数字、下划线或横线；名称支持 1～80 字。
存档包含助手的令牌、Cookie、设备信息及身份摘要，存放在 `accounts\<内部编号>\session.dpapi`。
`accounts.json` 只记录编号、名称和当前选择；根目录 `session.dpapi` 是当前账号的兼容副本。
实际读取以所选账号目录为准，缺少该文件时不会改用其他账号。
账号凭证与 Cookie 刷新会写回所选存档；浏览器登录、DMM 导入及自动续期先在临时文件中检查身份，身份不符时保留原存档。
尚未绑定身份的旧快照可以在有效状态下启动一次以绑定；已过期且无法确认身份时需重新登录并保存为新账号。

「保存当前登录态」可以用相同编号显式替换该编号的存档；「新账号登录并保存」要求新编号。
替换时先写新快照再切换索引，保留旧快照文件便于恢复。
游戏安装与更新文件为所有账号共享。这里切换的是助手登录文件，不修改 DMM Player 原始文件、游戏本地缓存或整个 Windows 用户资料。
DPAPI 存档依赖当前 Windows 用户，复制到其他电脑或用户后通常无法直接解密。

## 账号任务配置与批量运行

侧栏「账号配置」采用 ok-end-field 的 `ConfigCard` 编辑方式和运行时账号覆盖机制，并复用 ok-gm 已有的账号覆盖存储。
先在启动器保存账号，再在账号配置页选择编号与任务，修改参数并点击「保存账号任务配置」。
保存的是该账号的完整可编辑任务参数快照，其他账号和普通任务页的基准配置不变。
「恢复使用任务默认配置」删除该任务的账号覆盖，重新继承普通任务页的当前参数。
未点击保存的修改仅作为本次窗口内的草稿，切换选择时保留草稿；重启软件后不保留。

登录存档通过编号映射到稳定的 `dmm_<编号>` 配置 ID，重存登录文件或改名不会丢失任务配置。
参数保存在配置目录的 `account_scoped_overrides.json`，不包含登录令牌或节点凭据。
已有相同编号的旧任务覆盖会复制到稳定 ID，同时保留旧记录；不迁移未知账号名称或手机号。
账号配置只在任务运行时生效，运行期间账号编辑器锁定，也禁止在启动器页面手动修改登录账号。
普通任务卡片的配置控件与重置按钮也会在运行时锁定，采用 ok-end-field 的任务配置锁定补丁方式。

日常任务默认开启「多账户独立配置」，默认关闭「多账户模式」。
普通运行使用启动器当前账号及其任务参数；开启多账户模式后，可在「账号列表」每行填写一个保存的编号。
账号列表留空时使用启动器中已保存的全部账号，按保存顺序执行；重复编号只执行一次，未保存的编号会报错。
每轮执行前请求关闭当前安装目录中的游戏，确认退出后切换登录文件，再经框架启动流程自动更新并启动。
关闭超时会停止，不强制杀死游戏；只有窗口出现仍不代表进入主页，原有主界面检测继续负责确认可执行任务。
批量日常属于实际游戏操作，不会作为开发验证自动运行。

## 框架升级与启动集成

框架已从 1.0.179 升级至 [ok-script 2.0.8](https://pypi.org/project/ok-script/2.0.8/)，安装 `default` 与 `qt` extras。
依赖锁定以 `pyproject.toml` / `uv.lock` 为准，`requirements.txt` 由 uv 导出。
GUI 使用新的 `gui.type=qt` 配置，启用原生 `windows.start_exe`；`calculate_pc_exe_path` 从 DMM 安装配置解析游戏路径。
独立的 `LauncherTask` 已删除，更新和凭证获取在原生 StartController 创建游戏进程前执行，窗口稳定及截图检测仍由框架负责。
下载时间不占用进程创建后的窗口等待时限。

命令行入口也会加载同一配置与启动集成：

```powershell
.\.venv\Scripts\python.exe -m ok gui
.\.venv\Scripts\python.exe -m ok run_task DailyTask
```

`run_task DailyTask` 会实际执行日常任务。这里记录用法，不以运行日常任务作为升级验收，避免误触游戏内操作。
原有 `main.py` / `main_debug.py` 入口保留。打包程序需重新构建后才能包含这些源码变化。

`src/patches/startup.py` 在配置导入时幂等安装，覆盖直接运行与框架 CLI 两种入口：

- 原生 `execute` 的学马仕分支调用共享启动服务，将检查更新、登录和启动放在同一进程锁内；凭证不经过框架的原始参数日志或 shell。
- 其他本地程序使用 argv 与 `shell=False`，输出写入 DEVNULL，修复上游未读取 PIPE 导致阻塞的问题；`os.startfile` 的空参数传空字符串。
- 修复 Win32 overlay 自定义 `POINT` 污染共享 ctypes 函数签名，与 pyautogui 的标准 `wintypes.POINT` 兼容。
- 保留窗口在枚举期间消失时的 Win32 1400 容错，同时更新截图模块已导入的引用。

其他仓库的配置、OCR、任务页面等补丁未直接搬入；本项目未发现需要它们的对应冲突。

## 本机使用

在仓库根目录的 PowerShell 中运行：

```powershell
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m src.dmm login
.\.venv\Scripts\python.exe -m src.dmm status
.\.venv\Scripts\python.exe -m src.dmm check
.\.venv\Scripts\python.exe -m src.dmm update
.\.venv\Scripts\python.exe -m src.dmm launch
.\.venv\Scripts\python.exe -m src.dmm launch --fixed-node
```

`login` 打开 Windows 默认浏览器，使用该浏览器正常的登录态和已保存密码。
登录期间会临时把 Windows 系统代理设为 `--proxy` 指定的本地入口，并移除 DMM 的直连例外；
同时通知已经运行的浏览器重新加载代理设置，因此不需要关闭个人浏览器。
该设置在登录期间影响使用系统代理的应用；本机原本已使用同一入口时，实际变化主要是 DMM 不再绕过代理。
登录完成、Ctrl+C 取消、异常或 10 分钟超时后自动恢复；如果期间你或 v2rayN 修改了代理，则保留新的设置。
助手不修改 v2rayN 的持久化配置或节点选择。
如果进程被强制终止，恢复记录保存在助手目录；下次运行任意助手命令会恢复，也可单独运行
`.\.venv\Scripts\python.exe -m src.dmm restore-proxy`。
在 DMM 登录成功页按 `Ctrl+L`、`Ctrl+C` 复制地址即可，助手会识别授权码并换取凭证。
不要将成功页地址、密码、验证码发送到聊天或日志。
此模式不会导出浏览器密码或 Cookie；凭证过期且助手 Cookie 无法续期时，需要再次通过常用浏览器授权。

`login --browser private` 使用临时 Edge 窗口，自动接收成功页并保存该窗口的 DMM Cookie。
这类 Cookie 和 API 更新的 Cookie 会随会话加密保存，便于尝试自动续期。临时窗口没有个人浏览器的密码资料。

`import` 只读复制 DMM Player 登录态；所选账号已绑定身份时先校验匹配，再更新对应存档。
`status` 检查服务器是否认可凭证。
`check` 获取启动信息与清单，报告需要更新的文件数量和下载大小；若上次文件替换中断，会先恢复原文件。
`update` 校验与更新文件；`launch` 默认先更新再请求新的参数，使用 `--no-update` 可在需要更新时停止。
这些命令不会写回 DMM Player 的认证文件、Cookie 数据库、安装配置或启动日志。

默认入口为 `http://127.0.0.1:10808`，可以通过 `--proxy` 或 GUI 配置修改。
外部代理模式需先在 v2rayN 选择日本节点，并确认 DMM 域名的分流；入口地址不会固定节点。
独立节点模式通过 GUI 启用，独立助手 CLI 则显式加 `--fixed-node`；两种入口共享所选账号与加密节点。
登录浏览器在登录期间临时使用指定代理，API、续期与下载也显式使用同一入口。
私有 Edge 模式使用进程内代理，不修改系统代理。

Windows 临时代理使用微软的 [WinINet 连接设置 API](https://learn.microsoft.com/en-us/windows/win32/wininet/setting-and-retrieving-internet-options)。

## 会话与更新

- 会话位于 `%LOCALAPPDATA%\ok-gm\dmm-helper\session.dpapi`，通过 Windows DPAPI 加密，只能由对应 Windows 用户解密。
- 原 DMM Electron `v10` AES-GCM 凭证与 DMM Cookie 可导入；其他加密格式会明确报错。
- 当前验证的客户端流程没有 refresh-token 接口，使用有效 Cookie 取得 OAuth 授权码，再调用凭证签发接口。
- API Cookie 在每次响应后持久化；启动响应中的 `access_token_info` 会更新助手会话，避免继续使用旧平台凭证。
- 不会记录完整网络异常、签名下载地址或游戏启动参数。
- 下载先写入游戏目录内 `.ok-gm-update\staging`，按大小和清单 MD5 校验。
- Range 断点续传支持连接中断；错误范围响应和哈希失败不会替换已有游戏文件。
- 所有下载完成后才替换文件，备份与事务记录位于 `.ok-gm-update`；替换失败会回滚，下次运行也会恢复未完成的替换。
- 清单中的受保护文件保留现有内容；官方清单要求删除的文件通过备份后移除。助手不移除清单之外的游戏文件。
- 更新期间游戏、DMM Player 和 Celestite 必须关闭；助手不关闭你的现有进程。
- 服务器要求管理员启动时，助手需已经以管理员身份运行；不自动提升权限。
- 更新完成后 DMM 的安装版本记录仍可能旧于实际文件，助手通过文件清单判断状态。

## 当前实测边界

本轮实测：日本东京出口能访问新版 DMM API，旧凭证返回 `result: false`，旧 Cookie 未能自动授权。
常用浏览器登录后，助手已有有效加密会话；复制成功页的另一次凭证签发返回了 348，可能被 DMM Player 接收或授权码已失效。
新版启动和分页清单接口已验证：服务器 3.4.1，清单 143 个文件，本机需更新 7 个文件，约 280 MiB。
已完成真实更新：7 个文件、293,486,492 字节下载，更新后 143 个文件通过校验，版本 3.4.1；
已用服务器返回的新参数创建游戏进程。实际进入游戏主页仍未完成可靠验证。
DMM Player 正在运行时 Cookie 数据库可能锁定，import 会只导入独立凭证。
出现游戏窗口只说明进程创建了窗口，不能证明游戏登录成功。
「更新后必须先经 DMM 启动一次」的准确原因仍未确定。

独立 Xray 已使用本机内核完成离线配置校验、独立回环监听与进程退出实测；多账号使用临时加密样本验证隔离、切换、续期和错误账号保护。
节点列表已通过真实本机 Xray 的离线故障切换实测：不可用节点失败后，第二个节点成功访问本地测试服务。
账号任务参数隔离、登录快照替换后保留配置、批量账号上下文、运行时编辑锁及下载断点换节点均已由测试覆盖。
真实日本节点及两个真实账号的完整登录、更新和切换仍需使用者提供节点并在软件内登录后验证。

接口参考：[DMMGamePlayerFastLauncher](https://github.com/fa0311/DMMGamePlayerFastLauncher)；
与本机 DMM Player 5.5.20 的认证和启动接口名称交叉核验。实现未复制第三方启动器代码。
